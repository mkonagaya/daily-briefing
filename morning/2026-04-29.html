pgBackRest、13年の歴史に幕
リードメンテナがプロジェクト終了を宣言

数十億ドル規模のテック企業がOSS労働の上にフリーライドし続ける構造が限界に達した、2026年のOSSの典型構図。バックアップ戦略の見直しが急務に。

PostgreSQLエコシステムにとって地味だが致命的なニュース。pgBackRest はDR(Disaster Recovery)シナリオの事実上の標準バックアップツールで、AWS RDS、Azure、GCPなど大手クラウドのPostgreSQLバックアップ機構の裏側でも使われてきた。リードメンテナのDavid Steele氏が4月27日、プロジェクトを正式終了。

理由は明確で、「数十億ドル規模のテック企業がOSS労働の上にフリーライドし続ける構造」が限界に達したという、これまで何度も語られてきた持続可能性問題の最新事例。Snowflake が Crunchy Data を$2.5億で買収、Databricks が Neon を$10億で買収というPostgreSQL周辺の好景気の真裏で、無償メンテナがバーンアウトする — 2026年のOSSの典型構図。

geech的に重要なポイント:

  • 代替手段の検討が急務: pg_basebackup + WAL archiving の素朴な構成、Barman、wal-g など
  • バックアップ戦略の社内ドキュメント化は、ZipAir のようなエンタープライズ案件では監査要件
  • 「使ってるOSSのbus factor」をスタックレビュー時に確認する文化が、フリーランス・契約締結前のリスク評価項目として重要度を増す

出典: Medium PostgreSQL Blogs / pgBackRest GitHub
