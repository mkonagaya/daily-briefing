GitHub に CVSS 8.7 のRCE脆弱性
「git push 一発」で任意コード実行可能だった

Wiz が3月に発見、GitHub が修正済み (CVE-2026-3854)。push option の値が内部サービスヘッダーで適切にエスケープされていなかったコマンドインジェクション。GitHub.com と Enterprise Server 双方が影響。

push 権限を持つ攻撃者が git push 一発で GitHub のインスタンス上で任意コード実行できる、というクラスの脆弱性。原因は内部ヘッダーフォーマットで使われていたデリミタ文字が、ユーザー入力にも出現し得るものだったこと。crafted な push option を投げることで内部ヘッダーに追加メタデータフィールドを注入できた、というのが GitHub Advisory での説明。

GitHub.com 側は既に修正済み、Enterprise Server を自前で運用している現場は要パッチ確認。Wiz が3月4日に報告、GitHub が検証して修正をデプロイ、という標準的な responsible disclosure フロー。

geech的に重要なポイント:

  • 「内部処理の区切り文字とユーザー入力のサニタイズ漏れ」という古典的なバグが、現代の最重要インフラの中心で起きている。CSV injectionや command injection の系譜。
  • ZipAir LCC のように GitHub Enterprise Server をオンプレで運用しているケース はクライアント側のIT部門にパッチ状況の確認を投げておくと安全。
  • 「push 権限を持つ攻撃者」がトリガなので、組織内の侵害済みアカウントから横展開される可能性。MFA徹底とアクセス監査の重要性が改めて。

出典: The Hacker News / GitHub Advisory Database / Wiz Blog

Linux 7.0 が PostgreSQL の throughput を半減させた件、深掘り解説が出る

The Coder Cafe が4月29日に詳細記事公開。原因は「shared_buffers 120GB = 約3,100万 minor page fault」 + spinlock 競合。PREEMPT_NONE 削除でロックホルダーがプリエンプトされやすくなった結果、StrategyGetBuffer 周辺の spinlock 待ちが爆発。Ubuntu 26.04 LTS が Linux 7.0 を載せて出るため、現場では shared_buffers サイズ調整 + huge pages 利用 + sysctl チューニングで凌ぐ運用が広がる。

出典: The Coder Cafe / Phoronix
