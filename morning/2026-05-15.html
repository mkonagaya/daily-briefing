NGINX に18年間気付かれなかったヒープバッファオーバーフロー
"NGINX Rift" (CVE-2026-42945, CVSS 9.2)

rewrite ディレクティブと無名 PCRE キャプチャ + クエスチョンマーク付き置換文字列の組み合わせで、認証不要の RCE / DoS が成立。NGINX Plus / Open Source 全バージョンが影響、F5 が水曜にアドバイザリ公開。Web の前段に NGINX を置く現場 (=ほぼ全員) が要対応。

depthfirst によって発見、F5 が5月13日に公開。ngx_http_rewrite_module のヒープバッファオーバーフローで、rewrite → rewrite|if|set という連鎖と、$1, $2 など名前のない PCRE キャプチャに ? を含む置換文字列が組み合わさったときに発火。「18年間検出されなかった」というのは決して誇張ではなく、NGINX 1.0 リリース (2011年) を含めて、たぶんもっと古い時代から潜伏していた可能性が高い。

Konaのスタックを考えると、これは ZipAir LCC のフロントエンド配信、私の保健室 LIFF、shift-smith の API ゲートウェイなど、ほぼ全案件のリバースプロキシに直撃する話。AWS ALB / CloudFront 経由のケースは影響が限定的だが、EC2 / ECS / GKE のサイドカーで NGINX を立てているならパッチ必須。確認ポイントは2つ:

  • nginx.conf に rewrite が含まれているか: SPA の history fallback、Rails / Laravel の try_files 周辺、Next.js のリダイレクト設定など。多くの現場で使われている。
  • F5 NGINX Plus を使っている場合、サポート契約経由の自動更新の有無: NGINX Open Source は手動更新 (apt / yum)。

さらに今週は Cisco Catalyst SD-WAN Controller の peering authentication bypass (CVE-2026-20182, CVSS 10.0)、PaloAlto PAN-OS RCE が active use 中など、ネットワーク機器の critical 脆弱性が連発。パッチ運用の「週次サイクル」では完全に間に合わない週。CVE 公開 → 実環境悪用までの平均時間は、Mandiant M-Trends 2026 が「mean time to exploit = -7日」(つまり0day) と報告するレベルにまで縮小している。

出典: The Hacker News / F5 Security Advisory (K000156281)

Linux Atomic Writes が DB 向けに本格化 — torn page 対策の根本解決へ

PostgreSQL では Full Page Image (FPI) を WAL に書いて torn write を防ぐ既存の二重書き込み戦略があるが、atomic writes 対応 NVMe + Direct IO で根本的に不要になる可能性。現状は Direct IO 限定で、Buffered IO への展開は未定。QEMU でも NVMe atomic operations のエミュレートが可能になりつつあり、検証環境構築のハードルが下がっている。中長期で WAL 設計の前提が変わる話。
